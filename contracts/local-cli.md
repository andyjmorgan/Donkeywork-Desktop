# Local agent CLI contract — 0.2.0 (M1a)

This is an original, separate local protocol: `dwdesktop.local` version `0.2.0`. It does not amend or replace the M1b broker/browser draft `0.1.0`. Its schema is `schemas/local-cli.schema.json`, examples are `fixtures/local-cli.json`, and executable invariants are in `local-cli-model.mjs`. Passing these tests is not runtime authentication, capture or OS validation.

## Trust boundary

The daemon exposes a dedicated local CLI Unix-domain socket, distinct from the trusted broker IPC socket. A service-owned directory and restrictive socket permissions are required but are insufficient alone. On every accepted connection, the daemon reads the kernel's peer UID (`SO_PEERCRED` on Linux) and looks up an explicit UID policy mapping to allowed capability names and one fixed OS account/shell profile. Deny unmapped UIDs, including UID 0 if unmapped. Never accept UID, principal, permissions, executable, environment or account overrides from client messages. The CLI verifies the server UID against its configured service identity. A pathname or claimed JSON identity is not authentication.

Only capabilities actually supported by the selected backend may be reported. Permission names are inherited from 0.1.0: `desktop.view`, `desktop.control`, `desktop.resize`, `clipboard.read`, `clipboard.write`, `terminal.open`, `terminal.input`. Clipboard has no M1a operation. This endpoint never accepts broker grant, attachment or renewal assertions. No Keycloak/broker HTTP route is implied; remote CLI authentication is deferred.

Sessions belong to the verified UID and fixed profile. Every request rechecks ownership, current policy, session ID/epoch and required permission before side effects. Policy reload/revocation invalidates affected leases and sessions, releases held input and terminates PTY process groups. A new connection always repeats UID verification; a session identifier is never a bearer credential. Root can compromise a host regardless of this protocol; do not claim hostile same-UID isolation.

## Records and response correlation

Each record is a uint32 big-endian JSON-header byte length, that many strictly valid UTF-8 JSON bytes, then exactly `payload.payloadBytes` binary bytes **only** for `screenshot.result`. Header limit: 65,536 bytes. PNG payload limit: 67,108,864 bytes. All other records have zero trailing binary bytes. No video/base64 screenshots, compression of envelopes or undeclared binary uploads. A screenshot header and its body are indivisible: terminal events can occur before/after, never inside the body. Enforce lengths before allocating; truncated records, malformed JSON/UTF-8, invalid schemas, unexpected binary bodies and oversize framing close the connection. A semantic error on a valid request returns a correlated `error` with no side effects.

Every envelope has protocol, exact version, type, UUID `messageId`, payload, and session ID/epoch when its schema requires them. Replies have a new messageId and top-level `requestMessageId` echoing the request; `error` is unbound so it can reject unknown sessions. Unknown fields and types fail validation. Numeric counters fit exact JSON integers. Requests with no dedicated result receive `ack`. Asynchronous terminal output/gap/exit have no requestMessageId. Replies may arrive out of order; binary records remain serialized. Limit each connection to 16 in-flight requests and two sessions per UID, with one PTY per session. Reject excess work with `resource_exhausted`.

`messageId` also keys safe request idempotency for 120 seconds per UID/session. Identical retry of session.open, terminal.open, close or resize returns its recorded result; changed parameters with the same ID fail `invalid_argument`. While pending, retries join the original operation. Record at most 256 results per UID; reject excess new idempotent operations until entries expire instead of evicting a live guarantee. Input is intentionally excluded: never replay uncertain input automatically, and stale input sequences are rejected. Describe/screenshot retries are new requests with new IDs; each screenshot performs a new capture.

## Exact operation surface

| Request | Reply | Permission and semantics |
|---|---|---|
| `describe` | `describe.result` | Mapped UID; policy-filtered permissions, fixed profile and actual displays/modes |
| `session.open` | `session.opened` | Mapped UID with at least one usable capability; fixed profile only, ready result within 15 seconds or initialization_failed with cleanup |
| `session.close` | `ack` | Owner; idempotently release leases and terminate the PTY process group |
| `control.acquire` | `control.granted` | desktop.control; exclusive lease on the physical console across all sessions/UIDs; conflict does not implicitly take over |
| `control.renew` | `control.granted` | Current owning connection/UID/session/lease and current desktop.control policy |
| `control.release` | `ack` | Current owner; release held keys/buttons; already released lease is idempotent |
| `screenshot.request` | `screenshot.result` + PNG | desktop.view; no input lease |
| `input.pointer`, `input.key`, `input.text`, `input.reset` | `ack` | desktop.control plus current lease |
| `display.resize` | `display.resize.result` | desktop.resize plus current input lease |
| `terminal.open` | `terminal.opened` | terminal.open; profile comes from UID policy, one PTY per session |
| `terminal.input` | `terminal.inputAck` | terminal.input |
| `terminal.resize`, `terminal.close` | `ack` | terminal.input; close idempotent |
| `terminal.resume` | `terminal.resumed`, then gap/replay/live | terminal.open plus current owner; terminal.resumed reports sequence baselines |

All bound operations may return `error`. Session close also cancels pending screenshot/input work; no new side effects begin after closure. PTY exit is an asynchronous `terminal.exit`. Desktop topology is refreshed by describe or screenshot; resize returns the confirmed revision. `unsupported_capability` means a backend genuinely cannot perform the operation. Failure is never simulated success.

Sessions survive a lost connection for at most 120 seconds, then close and clean up. Reconnecting under the same authorized UID may reuse its session ID/epoch. Desktop leases never survive disconnect. There is at most one active terminal attachment/writer per PTY; a competing resume/open fails control_conflict. Worker restart invalidates all session epochs and returns not_found/stale_epoch, never aliases an old session to a fresh resource.

## Screenshot and input invariants

`screenshot.request` names one display and cursor preference. Capture must acquire a frame **after request acceptance**, from the same capture source intended for future streaming, within five seconds or return capture_failed. Do not serve a previous screenshot or latest cached frame. An unchanged desktop may of course produce identical pixels. Full native, post-rotation display raster only: no scaling, downsampling, compositing multiple displays or silent crop. Reject displays exceeding 4096×4096.

The result binds a new snapshotId to session/epoch, displayId, topologyRevision, width/height, actual cursorEmbedded and captureTimeUs (microseconds from this session's monotonic origin). Snapshot metadata corresponds to the acquired frame atomically. If topology changes during capture, discard/retry within the deadline or return stale_topology. includeCursor must be honored or fail unsupported_capability; actual cursor state cannot silently differ. The image is a static PNG, RGBA8, with width and height matching metadata. Both dimensions are 1..4096; checked width×height×4 must be ≤67,108,864 bytes, independently of compressed size. Validate PNG signature/IHDR, bit depth 8, colour type 6, dimensions and bounded inflate before allocation; reject APNG/animation, mismatched dimensions and truncation. PNG filter-byte overhead may be bounded separately by height×(width×4+1); decoded pixel allocation remains capped at 64 MiB. No unbounded ancillary-chunk allocation. A 3840×2160 raster is 33,177,600 decoded bytes.

Retain at most 32 snapshot metadata entries per session for 120 seconds; image pixels need not be cached. Unknown/evicted snapshot IDs return not_found and require a fresh capture. Pointer, key and text requests name a snapshot, display and topology revision. Require they match each other and current topology; stale_topology causes no injection and no coordinate rescaling. This checks geometry, not whether an application moved a button since capture.

Coordinates are display-local, post-rotation physical pixels, 0 ≤ x < width and 0 ≤ y < height. Pointer move requires button=none; down/up/click require a real button. Click is one down/up pair. Keys use USB HID usage page 7; text is explicit Unicode insertion and rejects unsupported characters rather than corrupting them. inputSequence is contiguous from 1 for each new lease; a sequence is consumed once accepted even if OS injection later partially fails. Duplicate/out-of-order input is stale_sequence. A partial injection returns an error and releases held input; it is never retried automatically. input.reset releases held keys/buttons and does not require a snapshot, so it remains possible during geometry transitions.

Control lease deadline is worker-monotonic, ≤45 seconds; renew every 15 seconds when a CLI keeps control. Renewal grants a new deadline only after current policy and unexpired ownership checks. No longer agent convenience timeout is introduced. Expiry, disconnect, revoke, close and failed injection release held input. Check lease validity immediately before each OS action, including each key in text insertion; cancel remaining actions on expiry/revocation. There are no arbitrary unbounded input batches.

## Resolution and terminal

Resize validates lease, supported mode and current topology before OS action. Serialize mode changes, release held input and suspend coordinate-bearing input until actual state is known. Confirm the actual host mode within five seconds. Applied mode changes increment topologyRevision and invalidate old snapshots; session/epoch and PTY stay unchanged. Unsupported modes return rejected/unsupported_mode with current actual dimensions. OS failure attempts rollback; report rejected/os_failed if restored, rejected/rollback_failed with actual dimensions/revision if not. Never claim a prior mode after failed rollback. If the display disappears, return capture_failed and refresh describe; no invented geometry. UI zoom and encoder downsampling do not count.

Terminal payload semantics adapt the 0.1.0 byte/sequence contract, with local UID authorization replacing attachment grants and no client-selected profile. Raw PTY chunks use canonical base64, at most 32,768 decoded bytes per local-v0.2.0 chunk, so base64 and metadata fit the 64 KiB header limit. Validate decoded size/canonical encoding as runtime semantics. Use process-group cleanup and sanitized environment. Output sequence starts at 1; replay is bounded to 4 MiB and 120 seconds. Disconnect retains the process ≤120 seconds. Resume reports last accepted input/resize and latest output sequence, then emits any gap, replays strictly after lastOutputSequence and atomically switches to live. A request beyond latest output is invalid_argument. Empty history after eviction uses earliestAvailableSequence=latestSequence+1. Missing output is explicit; no complete emulator-state reconstruction is claimed.

Input/resize sequences are per PTY lifetime; terminal.resumed supplies the next writer's baselines. Do not resend unacknowledged input after ambiguous delivery; a resumed writer starts at lastAcceptedInputSequence+1. Resize sequence increases independently. Exit follows final output with exactly one of exitCode/signal non-null and finalOutputSequence. Repeated close is safe. Slow consumers must not cause unbounded buffering: disconnect a lagging terminal attachment, retain bounded replay, and require resume. Never log PTY bytes, keystrokes, clipboard or secrets.

## Rust component seam

The integrator owns root manifests and any future shared wire/types crate. Initially each assigned lane may use a standalone Cargo package and local wire types, provided serialization conforms exactly to these canonical schemas and fixtures; no private protocol variants. The integrator later consolidates shared types. Core/capture owners must agree their Rust backend API before integration; this wire contract does not invent that in-process API. CLI owns framing/client calls; core owns peer policy, sessions, leases, dispatch and result correlation. Capture supplies acquire-next-native-frame, topology and confirmed resize behind the shared interface; input injection belongs behind the same display-coordinate model. Terminal supplies PTY lifecycle/byte events and never authorizes its own caller. Core passes already validated typed requests and cancellation/deadline context to components; components recheck OS facts and report real errors. No component accepts a raw broker assertion from this socket. Contract/fixture changes require integrator review.
